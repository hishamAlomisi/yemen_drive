# الرئيسية واختيار الخدمة والسعر — 19 أكتوبر 2026

## السلوك

- الرئيسية تعرض الخريطة وحاوية قابلة للسحب بين 12% و64% و90% من المساحة. أنواع الخدمات شريط أفقي من ServiceKindModel، مع علامة صح للنوع المختار/الافتراضي من الخادم. أسفلها شريط عناصر ServiceCatalogModel الخاص بذلك النوع.
- زر البحث عن الموقع وسطرَا الانطلاق والوجهة يستخدمان شاشة البحث القائمة. يظهر سطرا العنوان وتفاصيل الوصول مع اكتمال اختيار النقطتين. تفاصيل الوصول ما زالت قابلة للإدخال بالطريقة السابقة.
- الضغط على عنصر خدمة يحفظ اختياره. عند غياب طريق صالح تُفتح شاشة البحث، وبعد اختيار الموقع وحساب الطريق تنخفض الحاوية وتُؤطَّر الخريطة لإظهار الطريق، ثم تُفتح شاشة السعر تلقائيًا. الرجوع من البحث يلغي نية الانتقال؛ تحديث GPS وحده لا ينقل المستخدم.
- اختيار الموقع على الخريطة يحتفظ بالعملية المعلقة حتى تحديد النقطة أو إلغائها، دون إعادة تصميم شاشة البحث.
- في شاشة البحث خيار «تحديد موقعي الحالي» فوق خيار الخريطة. يملأ GPS الحقل المحدد (الانطلاق أو الوجهة)، ويعرض مؤشر تحميل ويمنع تكرار الطلب أثناء الجلب. عند نجاح التحديد يعيد نتيجة الاختيار لمسار الحجز القائم؛ تبقى إمكانية البحث اليدوي مستقلة عن صلاحية GPS.
- البحث بالاسم والأماكن المحفوظة واختيار نقطة على الخريطة لا تشترط GPS أو صلاحية موقع الجهاز. حقل الانطلاق يقبل أي مكان، وحقل الوجهة يمكن اختياره أولًا أيضًا. طلب الصلاحية ورسالة تعذر GPS يخصان استخدام «موقعي الحالي» فقط؛ محاولة الموقع الأولية صامتة ولا تستبدل انطلاقًا اختاره المستخدم أثناء انتظارها.
- شاشة السعر تعرض الخدمات في قائمة رأسية، وسعر كل خدمة من PricingModel.report للمسار الفعلي. تُرسل ثلاثة طلبات تسعير متزامنة كحد أقصى، وتُحفظ النتائج للمسار والنوع وقائمة العناصر نفسها. تبديل الاختيار يعيد استخدام التسعيرة؛ تغير المسار يبطلها ويهمل النتائج المتأخرة.
- تحميل الكتالوج لا يختار أول عنصر تلقائيًا. إن كان عنصر مختارًا في الرئيسية يُحفظ للشاشة التالية؛ وإلا يظل البحث معطلًا حتى اختيار عنصر وتسعيره بنجاح.
- تظهر أزرار الزيادة والنقصان وتعديل الأجرة داخل بطاقة العنصر المختار فقط. الحاوية قابلة للسحب بين 18% و62% و98%، وشريط البحث والدفع والخيارات ثابت أسفل الشاشة في الوضعين الفاتح والداكن.
- الفاتورة وتفاصيل الوصول متاحة من أيقونة المعلومات والخيارات. الفاتورة تجمع الأجرة ورسوم الخدمة القائمة. لم تُضف حدود أجرة أو أوقات وصول أو أوصاف وهمية؛ تظهر البيانات المتاحة من الخادم فقط.
- خيار القبول التلقائي معطل افتراضيًا. عند تفعيله يقارن سعر العرض بالضبط مع أجرة الطلب المرسل، ثم يستدعي عملية قبول العرض الحالية في API. العروض المختلفة أو المنتهية لا تُقبل تلقائيًا، ويُمنع تكرار المحاولة للعرض نفسه.

## نطاق التغيير

ملفات العرض والحالة ضمن ride/booking، وربط الرئيسية والمسارات ضمن ملفات ride القائمة، مع تحديث ترجمات العربية والإنجليزية. لم تتغير عقود API أو قاعدة البيانات أو لوحة التحكم أو تطبيق السائق، ولا تحتاج هذه المرحلة migration.

## التحقق

نجحت اختبارات المشروع الـ53. تشمل البحث واختيار نقطتي المسار دون GPS، تحديد الوجهة على الخريطة قبل الانطلاق، حساب الأسعار وتجاهل النتائج المتأخرة، الاختيار الصريح وحفظه، منع إنشاء طلب أثناء المعاينة، الرجوع من البحث، حدود سحب الحاوية، ثبات الشريط السفلي، الوضعين الفاتح والداكن بعرض 390 و320 نقطة مع تكبير الخط، وقبول السعر المطابق عبر مستودع API بديل داخل الاختبار.

تحليل الملفات المعدلة دون أخطاء أو تحذيرات؛ توجد ملاحظات أسلوبية في الملفات القائمة. تحليل location_selection_controller.dart بعد إصلاح الصلاحية خالٍ من الملاحظات. الاختبارات لا تنشئ رحلات أو دفعات حقيقية، وتستخدم بديلًا للخريطة الأصلية.

نجح بناء release المقسم لمعمارية x86_64 بعنوان API `http://192.168.89.72:5080/api`، وحجم APK المعروض 23.7MB. تم تثبيته تحديثًا على MEmu (`127.0.0.1:21533`) دون مسح بيانات التطبيق، وتشغيله وفتح شاشة البحث يدويًا دون رسالة منع الصلاحية. لقطة الفحص في `build/booking-previews/memu-search-check.png`. استخدمت أعلام تشغيل برمجية مؤقتة لمعالجة عرض الرسومات في المحاكي؛ لم تتغير إعدادات رسم النسخة في المشروع.
